1. System Overview & Architecture

The Hospital Management System REST API is a high-performance, enterprise-grade backend service built from the ground up to support modern healthcare operations. The system eliminates all frontend dependencies, operating strictly as a headless RESTful backend designed for integration with web applications, mobile apps, telemetry devices, and enterprise hospital information systems.

2. Security & Authentication Workflow

All sensitive hospital resources are guarded using Spring Security 6 and JJWT. Unauthenticated requests to protected endpoints return 403 Forbidden.

Authentication Flow

  1. Client transmits credentials via POST /api/auth/login.
  2. CustomUserDetailsService retrieves user record, verifies BCrypt hashed password.
  3. JwtTokenProvider generates signed JWT (HMAC-SHA256) containing username, user ID, and assigned roles.
  4. Client passes token in subsequent requests via HTTP header: 
    Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
  5. JwtAuthenticationFilter intercepts incoming traffic, parses and validates claims, and populates SecurityContextHolder.

3. Three Major Hospital Workflows

Workflow 1: Walk-In Patient Queue Flow

Walk-in patients arrive at the outpatient department without scheduled appointments. The system handles arrival sequencing atomically.

  • Deterministic Daily Tokens: Generates human-readable sequential tokens (W-001, W-002, W-003, ...) resetting at midnight.
  • Queue Progression Lifecycle: WAITING → CALLED → IN_CONSULTATION → COMPLETED (or CANCELLED)
  • Department Filtering: Live queue status viewable per department or hospital-wide.

Workflow 2: Emergency Clinical Triage Flow

Acute patients arriving at the emergency bay are triaged according to clinical acuity.

  • Acuity Ranking Hierarchy: CRITICAL > HIGH > MEDIUM > LOW
  • Triage Sorting Invariant: Active emergency queries (GET /api/emergency/active) always return CRITICAL patients first, sub-sorted by arrival timestamp.
  • Trauma Status Updates: Transitions from REGISTERED → TRIAGE → UNDER_TREATMENT → ADMITTED or DISCHARGED.

Workflow 3: Appointment Booking & Conflict Guard

Prevents scheduling collisions and ensures doctors are never double-booked.

  • Double-Booking Invariant: Before confirming a booking, AppointmentServiceImpl queries existing active bookings for that doctor at that specific date and time slot.
  • Collision Response: If occupied, the request is immediately rejected with DoubleBookingException (HTTP 409 Conflict).
  • Appointment Lifecycle: PENDING → CONFIRMED → CHECKED_IN → IN_CONSULTATION → COMPLETED

Inpatient Bed Lifecycle & Pharmacy Safety Rules

Bed Allocation & Release

  • Exclusive Allocation: Assigning an already occupied bed throws BedUnavailableException (HTTP 400).
  • Admission State Transition: On admission, bed is locked to OCCUPIED.
  • Discharge Auto-Release: Processing patient discharge automatically returns bed to AVAILABLE.

Pharmacy Dispensing Rules

  • Expiry Verification: Medications with expiryDate < today are rejected with ExpiredMedicineException.
  • Stock Invariant: Requests exceeding available quantity throw InsufficientStockException.
  • Atomic Stock Decrement: Transactions occur inside @Transactional boundaries.

{
  "firstName": "Jane",

Request Body:

Response: 200 OK — { "success": true, "token": "...", "user": { "id": 1, "email": "admin@hms.com", "role": "ADMIN" } }

Headers: Authorization: Bearer <token> — Returns authenticated user object.
